# 崩溃诊断

玩家遇到闪退后，重新打开原来使用的启动器，点击“导出诊断包”。不要先清理 `data` 目录。诊断包只保存在玩家选择的位置，不自动上传。

普通启动即启用小型异常记录，不需要管理员或另开采集器：

- 记录访问冲突等指定异常的时间、线程、模块标识、模块内偏移和最多 24 个处理器栈帧；
- 每个游戏进程保留最近 8 条，最多 32 KiB；
- 导出时按字段白名单重新生成 JSON，剔除任意附加字段；
- 不收集完整内存、寄存器、栈内存或存档内容。完整转储仍需单独同意。

## 维护者阅读顺序

1. 先核对诊断包里的运行版本和退出状态。`FirstChanceNotCrashVerdict` 表示异常曾发生，不代表它一定造成退出。
2. 查找 `exceptions/` 或 `runs/<run>/exceptions/` 中的记录，按时间、进程和异常偏移关联崩溃前日志。
3. 用该包构建时保留的 `artifacts/symbols/<release>-<timestamp>/MODULES.json` 对照模块时间戳、映像大小和 DLL SHA256，再用匹配的 PDB 解析偏移。构建脚本校验 PDB GUID/age，拒绝混用旧符号。符号仅供维护，不放进玩家包。

记录的是异常处理器调用栈，不是完整异常上下文展开。游戏自己处理的异常不会被拦截；强制结束、部分快速失败和栈耗尽可能来不及记录。内存被提前写坏时，异常位置可能只是受害位置，不能保证单靠诊断包就定位写坏者。


正式配置不带 F1～F8 手动开发采样入口；F5 接受邀请和 F9 自杀等正常操作保留。上述异常摘要、运行日志和导出能力不依赖这些开发按键。一次 FirstChance 记录不代表一次真实崩溃；导出包也不保证单凭日志就能定位任意闪退。匹配的 PDB 由构建端保留，不放入玩家包。
