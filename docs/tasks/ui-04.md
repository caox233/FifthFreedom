# UI-04 — explicit Public configuration and credential isolation

Status: ready-for-agent — production configuration/credential seams implemented;
Public UI and runtime remain unavailable. Windows DPAPI and new WPF assertions
require the next hosted Windows run; Linux source checks are separate evidence.

## Configuration boundary

`PublicDeploymentProfile` requires an explicit deployment ID, HTTPS control-plane
origin, IPv4 overlay CIDR and server address, typed Fast/Compatible transport,
QUIC/WSS peer URI with an explicit port, and immutable runtime input declarations.
There is no default endpoint or inherited donor deployment. Fast and Compatible
remain distinct from LAN Host/Join. HTTPS origins have authority only; user-info,
paths, query, fragment, whitespace/control characters and disguised IPv4 aliases
are rejected. Peer scheme must match the typed transport.

Overlay prefixes are explicitly limited to /8 through /30. Network alignment,
canonical dotted IPv4 spelling, server membership and usable host position are
required. Network/broadcast server addresses and overlays crossing zero,
loopback, link-local or multicast/reserved high-address ranges are rejected.
Public native endpoints must explicitly name the configured overlay server and
port; a missing identity/address/port does not select LAN or infer a deployment.

Configuration identity is a namespace, not proof that a publisher, endpoint or
TLS peer has been authenticated. The profile contains no tunnel secret or token.
Representations omit deployment endpoints, account names and input digests.
Normal TLS verification is still required by any future actual transport.

`PublicDeploymentRuntimePins.VerifyFiles` checks exact byte lengths and SHA256
for the four files named by the donor launcher: core, CLI, Packet.dll and
wintun.dll. It rejects linked paths and missing/changed bytes. It only checks
explicit input declarations; it does not download, execute, install or declare
Public ready. This four-file check is not the complete dependency closure:
WinDivert driver inputs, Npcap redistribution rights, Wintun notices and package
provenance remain their own gates. No runtime binary or driver was added.

## Credential implementation

`CredentialEnvironmentContext.Lan` and `ForPublic(profile)` create typed
`CredentialIdentity` values. The LAN scope remains byte-for-byte
`SCBL-LAN-DPAPI-v1` compatible, preserving existing filenames and current-user
DPAPI entropy. Existing string overloads are explicitly LAN-only wrappers.

Public scopes use a separate prefix and canonical JSON arrays containing the
explicit deployment ID, canonical HTTPS origin, overlay network/server, native
endpoint and username. Different deployments sharing an overlay IP cannot reuse
credentials; neither can the same ID with another HTTPS authority or server.
Changing Fast/Compatible alone preserves the same deployment account namespace.
Public usernames follow the existing launcher's ASCII character contract and
reject malformed Unicode/control characters. Scope/identity representations do
not print credentials or endpoints.

The actual `CredentialStore.Save`, `TryLoad`, `Load` and `Delete` implementations
accept the typed identity. Missing Public credentials never try a legacy LAN
filename. Current launcher load/save and recovery delete/save now use these
production methods. Recovery captures its identity and explicitly refuses the
unintegrated Public recovery path before making a request. Successful login
persists to the environment captured for that authentication, not a later current
selection.

The WPF credential-context seam clears manual passwords, auto-fill ownership and
all recovery inputs on a deployment change. Captured manual passwords are also
checked against their captured environment before authentication. Context changes
are blocked during operations, game startup/running, owned-session drain and
window shutdown. The seam does not activate Public networking. The Public UI
item remains disabled and the native startup gate is unchanged.

## Verification

```sh
DOTNET_ROOT=/workspace/.toolchains/dotnet /workspace/.toolchains/dotnet/dotnet run --project tests/PublicDeployment/PublicDeployment.csproj -c Release --no-launch-profile
DOTNET_ROOT=/workspace/.toolchains/dotnet /workspace/.toolchains/dotnet/dotnet build src/launcher/src/SplinterCellCNLauncher.csproj -c Release -p:EnableWindowsTargeting=true --no-restore -v minimal
python3 -B -m unittest discover -s tests/ui -v
```

Executed Linux result: **12 profile/credential cases passed**, exit 0; actual
Windows DPAPI case explicitly skipped. The project links the real production
classes, including the unchanged LAN `ServerAddress` parser moved to its own
file. Its sole test substitute rejects use of the launcher's default log-data
root; every storage check supplies an owned temporary directory. DPAPI and
credential methods are not mocked.

The suite covers legacy scope bytes, same-overlay isolation, changed authority
and server isolation, canonical origins, missing identity, bad URLs/CIDRs,
transport mismatches, malformed usernames, immutable pins, real file hash checks,
changed/missing files and a Linux symlink rejection. Production `TryLoad` and
`Delete` are exercised against other namespaces' synthetic files to prove there
is no filename fallback. A first run correctly failed a QUIC short-IPv4 negative
case: .NET classified that nonstandard-scheme host differently. Raw authority
validation was fixed; the complete suite then passed.

On Windows a thirteenth case uses actual current-user crypt32 DPAPI for LAN and
two Public identities, verifies independent save/load/delete, confirms plaintext
is absent, and rejects ciphertext copied into another deployment's filename.
Linux success does not establish that Windows result.

WPF cross-compilation passed with zero warnings/errors. All 12 existing source
UI contract tests passed. Five new assertions in the existing Windows no-game
`--self-test` cover actual context-change clearing, captured manual-password
rejection, cross-deployment autofill isolation, LAN restoration and retained
Public unavailability. They require hosted Windows execution before being called
passed. No game, driver, external network or real account was used. Ignored raw
receipts: `.local/cloud-receipts/ui04/`.
