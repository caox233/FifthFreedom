# CI-01: hosted component builds and explicit package admission

State: **ready-for-agent** — implementation is in the cloud branch; record the
actual GitHub run and resolve its build failures before claiming hosted builds
passed. This task is part of the six ordered migration milestones, not a reduced
replacement goal.

## Inputs and behavior

Source handoff: `fc8ef510b51be83c31f9f8233997f758b0477acc`. The existing
`scripts/build.py`, package hashes, and the two complete-resource assertions in
`tests/build/test_build.py` remain unchanged.

`.github/workflows/candidate-build.yml` registers GitHub-hosted Windows 2022 and
Ubuntu 24.04 jobs on pull requests, manual dispatch, and `codex/**` development
branch pushes. Push activation is explicitly authorized as a fallback when the
cloud session cannot reach the GitHub API. There is no tag trigger, self-hosted
runner, Release job, production deployment, game launch, or capture invocation.
All jobs have read-only repository permissions and actions pinned to full commit
IDs resolved from their official repositories.

- **Strict complete-package input gate:** executes the two unchanged resource
  tests and verifies the pinned input/hold manifests. Missing held inputs fail
  visibly. The full Windows package job depends on this gate succeeding.
- **Windows components:** builds the existing WPF project, production-feature x86
  hooks/gameplay DLLs and Windows LAN server independently of the package gate.
  It runs PortPlan, BackgroundTaskRegression, ObserverSession, NetworkEnvironment
  and native core/API checks. WPF save entries are existing wildcards: compiling absent SAV/META does
  not require placeholder saves, resource removal, or project edits. The exported
  self-contained executable is explicitly `FifthFreedom.component-only.exe`, accompanied by warnings
  that it is not an admitted/installable package. Its `--self-test` runs in a fresh
  entire executable-directory copy, since LogService uses `executable/data` rather
  than only APPDATA. Process exit, report presence, nonzero PASS count and exact
  RESULT summary must all agree. No `--lan-tools-self-test` runs in this lane.
- **Linux retained LAN baseline:** builds/tests the selected backend crates from
  `src/native`. A Linux binary is not evidence of an integrated Public deployment.
- **Linux public donor reference:** builds/tests the selected donor backend crates
  from `integration/scbl3` and runs its manager unit tests. It is reference evidence,
  not a second supported product or the final unified public server.
- **Full Windows package:** when inputs are admitted, invokes the original
  `python -B scripts/build.py all`; no separate weakened package implementation.
  It then runs isolated `--self-test` and `--lan-tools-self-test` against that
  admitted full package. The bundled-save probe therefore cannot run on incomplete
  compile-only resources.

Component artifacts contain explicit scope, source SHA, status, binary SHA256
checksums, notices, and build logs. A failed command retains its nonzero exit
status; artifacts are uploaded with `always()`. A failed build never gets a
successful component receipt. Artifacts are retained for 14 days.

## Tools and test isolation

Rust is `nightly-2025-10-15`, Cargo uses `--locked`, .NET reads the existing
`global.json` (10.0.302), and protoc is 35.1. The installer verifies TLS, the upstream
release asset SHA256, and `libprotoc 35.1`; a pre-existing tool directory is not
overwritten. Digests were read from the official protobuf v35.1 asset page:

- Linux x86_64: `6930ebf62bd4ea607b98fff052596c6ee564b9835b4ce172c75a3f53ae9d91b7`
- Windows x64: `5d3ff218d7d91eea95f7569bcb5a98f3030f8996d44151279d9772edcff76082`

Linux backend tests receive fresh, owned `SCBL_IDENTITY_TEST_DIR` and
`SCBL_RELEASE_TEST_DIR` directories. They never inherit a deployed account path;
SQLite and diagnostic inputs are synthetic. These fixture directories are removed
after the tests. Compiler concurrency is two jobs per runner.

## Remaining gates and rollback

Record actual hosted job URLs, commits and conclusions after pushing; Linux-side
script and workflow validation is not a Windows build result. GitHub API access is
a separate runtime-policy issue tracked by the root task. Complete packaging stays
blocked until approved matching input files or a reviewed reproducible replacement
are available and the privacy/publication metadata is updated. Do not upload held
saves to make CI green.

WPF rendering/DPI/IME, game graphics/audio, real LAN/Public networking and accepted
gameplay remain separate live-acceptance boundaries. Existing passed F3, MAC11,
Chinese/world-camera and VSS EMF scope must not be reopened just for this CI change.

Rollback is the inverse of the eventual CI implementation commit: restore the
prior root workflow and remove only its added `scripts/ci*`, `tests/ci/` and this
task record if deliberately reverting the feature. Do not reset other cloud work,
rewrite historical evidence, or change pinned package inputs.
