## 已收到的脱敏事实及优先级

以下来自本地四端审查的汇总，云端未读取原始日志、玩家标识或转储。
数目是该证据集中的观察，不是故障发生率或根因证明。

1. **摄影机投出同期闪退，优先**：约 29 秒窗口内房主及两客户端出现
   `0xc0000005 / Access=8 / Instruction=0`，没有可信返回调用点；第四端同期退出。
   另一例房主 `Access=1 / RVA=0x20c25b4` 独立记录，不合并归因。
   九份 trace 的 `SCBL_STICKY_CAMERA` 只有初始化，不是部署调用栈。
   检查投出、复制、组件未就绪、销毁、重复部署，保留已确认的单击/长按/双击行为；
   不猜偏移、不启动游戏、不把旁支防护当成已解释这次闪退。
2. **大于 56 级快速匹配，待定位**：25 次 SearchSessions 中 8 次空、17 次非空，
   没有按真实玩家等级标注；六次 `expired-coordination-window` 不证明等级因果。
   四次运行保留原生 56 行并报告 `allocation-range`，五次启用 999 行。
   审查实际分配尺寸、整段保护和区域边界，不删除安全判断、不修改真实等级或存档。
   55/56/57/高值、混队与单人的离线控制不能冒充真实多人同局验收。
3. **电磁镜性能，待定位**：需要逐帧前后 p95/p99 和开关对照。4039 次零尺寸绘制错误
   可属于另一条路径；计数不证明目镜卡顿。既有 VSS EMF 显示通过继续保留。
4. **包身份，分开处理**：新玩家截图为 `SCBL LAN / RELEASE_MISMATCH`；房主
   原生票据拒绝为 `PACKAGE_IDENTITY_REQUIRED`，799 条具有不同 ts/call/session 元组，
   不能说只是同一条日志重复，更不能关闭认证或一致性判断。
5. **独立兼容问题**：两台机器共四份记录中的定制地址表缺 `dx9`，每份三条。
   本地已用真实 loader 复现：合法 DX11-only 输入原版失败，只有 `dx9` 加默认空表后
   成功，恢复原字节再次失败；缺 DX11、畸形 DX9、坏哈希仍拒绝。
   云端按真实生产字段验证，输入兼容不恢复 DX9 UI。
6. **其它边界**：九份 trace 各一次端口 0 发送失败 10049，来源待查；
