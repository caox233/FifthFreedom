# UI-03 — production LAN environment ownership and WPF binding

Status: ready-for-agent — implemented; hosted Windows execution of this revision
and real host integration remain separate evidence gates. Public is unavailable.

## Result

The launcher constructs `NetworkEnvironmentController` and an actual Dispatcher
adapter. Host selection, Host preparation before launch, and orderly close now
use the controller's owned leases. The adapter invokes the retained
`HostRuntimeService` initialization, executable hash verification, fixed-port
planning and `LanConnection` capability/config/content readiness checks. Existing
package admission, account authentication and named-pipe game startup remain in
their original services. No game or capture is started by this change.

The UI keeps LAN/Public separate from Host/Join and Fast/Compatible. The Public
item stays disabled. The existing status light/text use real capability results;
the environment selector's availability and tooltip reflect the controller.
An offline Join selection is explicitly configured but not ready. This lets a
user leave an owned host before entering a remote endpoint without silently
restarting that host. Only an `IConfiguredLanJoinLease` for LAN Join receives this
exception; generic not-ready Host/Public candidates still fail and roll back.

The startup Join transaction is owned from construction, and its controls are
locked until it finishes. `WindowLoadedAsync` only awaits that transaction; it
cannot issue a late Join that overrides a user's Host choice. Initial Join
preserves saved endpoints, including an independently managed server on the same
machine. Restoring the previous client endpoint happens only after an owned Host
lease has actually stopped and drained its broadcast.

Every WPF/control and host mutation in the adapter executes on the Dispatcher.
Background controller activity reads use volatile flags; lease health is locked.
Host health also checks the retained owned process handle, so an exited host is
not presented ready until another network check. Owned cleanup is serialized,
idempotent and retryable on failure; no process enumeration or external-process
termination was added. Shutdown awaits dispatcher work asynchronously. Rollback
restores the actual Host/Join presentation before starting its broadcast.

Capability observations carry their originating lease, endpoint and bind address.
Success, failure and exception paths cannot publish into another generation or
a changed target, even if a replacement uses the same endpoint. A disposed lease
rejects late readiness updates. Capability-check elapsed time is optional; it is
not advertised as network round-trip latency or a live gameplay measurement.

## Exit-cleanup follow-up

Review found that normal and early game exit updated the idle UI before the
configuration session finished draining. `SetBusy(false)` therefore cached the
still-owned session and could leave Host/Join disabled after the later drain.
The monitor now calls `StopOwnedLaunchAndRefreshEnvironmentAsync`: it drains only
the captured session, then marshals back to WPF and re-reads the current session
before updating the environment controls. Closing windows do not receive that
publication; an older completion never blindly clears a newer session's lock.

Four additional Windows `--self-test` assertions construct actual unstarted
`GameLaunchService.LaunchSession` objects and owned `LaunchPipe` instances, then
exercise the real idle-UI → `StopAsync` → dispatcher refresh sequence, including
an obsolete session ID while a replacement remains owned. The probe does not
start a pump, execute a process, write a game file or read real credentials.
The amended WPF cross-build passed with zero warnings/errors; execution of these
new assertions remains subject to the next hosted Windows run. Receipt:
`.local/cloud-receipts/ui03/wpf-exit-cache-cross-build.txt`.
