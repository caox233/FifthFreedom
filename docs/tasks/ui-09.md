# UI-09 — Windows retained overlay session prerequisite

Status: **ready-for-agent**. Ordinary Public remains closed. This is the next
Windows ownership prerequisite after [UI-08](ui-08.md), not completion of the
live overlay lease or the six project goals.

The [pinned source patch pair](../dependency-patches/easytier-2.6.4-windows-session/README.md)
adds a real backend session observer and connects it to EasyTier's actual Windows
TUN creation path behind a separate development feature. The observer obtains
identity from the retained Wintun Session/Adapter, checks kernel LUID/GUID/index/
alias and optional current IPv4 state, and becomes permanently invalid when its
owner or receive worker ends or an observed identity/liveness check fails. It
holds only a Weak Session reference and cannot create a UI-08 transport lease.

Six executable pure Rust tests cover strict request names, owner loss while other
session references survive, weak-reference lifetime, all identity component
changes, sanitized kernel/worker failure and a late successful read after owner
revocation. The patched Windows backend with its actual async module passed
`cargo check --locked --features async --target i686-pc-windows-msvc` locally.
Both patches applied and reversed to exact original SHA256 values. The initial
full-caller check was syntax-only; the later hosted build below now verifies
actual Windows core/CLI code generation and linking with the paired backend.
No driver, core, game, overlay network or TUN was started for this task.

The official API imposes a concrete boundary. In Wintun 0.14.1 source at tag
commit `bfef136abfa1665c2592be09a7e383d646cdbe6e`, `api/adapter.c`'s
`NciSetAdapterName` handles a duplicate name by renaming the conflicting adapter;
`WintunCreateAdapter` invokes `DriverInstall`; `WintunCloseAdapter` queues orphaned
device cleanup. The requested GUID is not treated as an authoritative returned
interface GUID. In Rust wintun 0.5.0, `get_guid()` caches the request while
`get_luid()` queries the actual retained handle. These were source reads, not a
reproduction of the bundled DLL or actual driver behavior.

The new mode therefore **requests a new adapter without `Adapter::open`**, but
does not promise collision-free exclusive creation or zero unrelated system
effects. Its feature suppresses the extra firewall/registry calls in
`virtual_nic.rs`; official-driver effects, remaining interface/DNS/route changes
and a trustworthy installation directory still require explicit development
environment review. A wrapper cannot erase these API effects. A new custom
Wintun DLL, signed-driver product or additional empty admission factory was not
introduced.

Next executable work is a bounded retained-session probe using the now-built
paired backend, with driver execution only in an explicitly authorized disposable
Windows environment.
That probe checks actual returned identity, owner drop and async shutdown, and
records the bounded observed side effects. Interface down/rename/address-loss
execution remains a separate follow-up gate. Local owner IPC, secure-peer/process monitoring,
all game sockets and a reviewed production live-lease issuer remain unresolved;
the ordinary Public gate must not be opened from a name, snapshot, configuration
IP or return-pipe heartbeat.

canonical archives: 700 EasyTier files and 49 tun files, with combined source
SHA256 `0e01b494704e7a4f3afb67d7c54b446149fda7317938623d36164d0d53c0d1eb`.

lock transformation removes only the exact pinned tun Git source entry. Actual
